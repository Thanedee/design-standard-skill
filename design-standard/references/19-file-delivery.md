# 19. File preparation and delivery

Export each asset in the format its destination needs, at the exact size, in the right colour space, compressed without visible loss, named consistently, and delivered with its editable source and any licences.

### 19.1 Choosing the format

| Format | Use for | Avoid for |
| --- | --- | --- |
| JPG | Photographs and photo-heavy social posts (quality 80–92%) | Text-heavy graphics with flat colour (artefacts around letters) |
| PNG | Graphics with text, flat colour, transparency, screenshots | Large photos (heavy files) |
| WebP / AVIF | Website images (smaller than JPG/PNG at the same quality) | Platforms that don’t accept them; print |
| SVG | Logos, icons, illustrations on the web | Photographs |
| PDF | Print (PDF/X-4), documents, LinkedIn document carousels | Social single-image posts |
| MP4 (H.264/H.265) | Video for all social platforms | — |
| GIF | Avoid; use MP4 or animated WebP instead | Anything with many colours |
| Vector source (AI, EPS, SVG, PDF) | Logo masters and handover | — |

### 19.2 Export checklist

- Exact pixel size for the platform (section 11); export at 1× the canvas for social (platforms re-compress larger files anyway), 2× for websites on high-density screens.
- **sRGB** embedded for screen; printer’s CMYK profile for print.
- Social image under about 1–5 MB; website images usually under 200–500 KB; LinkedIn documents under 100 MB.
- Text-heavy social graphics: export PNG or high-quality JPG (90%+), then check letters at 100% for halos and blocking.
- Remove hidden layers, off-canvas elements and personal metadata you don’t want shared (but keep Content Credentials, section 17.7).
- Check the export file, not the working file, against section 20.

### 19.3 Naming and organisation

- Pattern: client\_project\_asset\_dimensions\_version\_date (section 18.5).
- One folder per project: /source, /exports, /assets (licensed images, fonts), /approved, /archive.
- Keep the approved master and its exports together; mark them clearly as APPROVED.

### 19.4 Handover package

- Final exports in every required size and format.
- Editable source files (Figma, Canva link, PSD, AI, INDD, Affinity) with linked assets packaged.
- Fonts list with licence status (never send font files the licence doesn’t allow to be shared).
- Image and music licences, model and property releases.
- Alt text and post copy for every social asset.
- A short usage note: where each asset goes, posting dates, what needs regulatory approval (ARCON) before use.

### 19.5 Storage hygiene

- Delete temporary files, relays, test exports and superseded drafts once the client approves, if requested.
- Back up approved masters in at least two places.
- Never store client personal data (CVs, IDs, contracts) in shared design folders longer than needed.
